# 八、技能系统

技能系统是 CountBot 的可扩展能力层，通过 Markdown 文件定义技能内容，让 AI 获得特定领域的知识和能力。

核心文件：`backend/modules/agent/skills.py`

## 1、技能系统架构

```
skills/                          # 内置技能目录（项目根目录下）
├── weather/                     # 天气技能（示例）
│   └── SKILL.md                # ★ 技能描述文件（必须）
├── email/
│   └── SKILL.md
├── baidu-search/
│   └── SKILL.md
└── ...

workspace/skills/                # 工作空间技能目录（用户自定义）
├── my-skill/
│   └── SKILL.md
└── ...
```

## 2、双目录加载机制

SkillsLoader 从两个目录加载技能，**工作空间优先**：

```
加载顺序：
  1. 工作空间技能（workspace/skills/）  ← 优先级最高
  2. 内置技能（项目根目录/skills/）      ← 补充加载

规则：
  - 如果工作空间中有同名技能 → 使用工作空间版本，跳过内置版本
  - 如果工作空间中没有该技能 → 使用内置版本
```

这种设计的好处：
- 用户可以在工作空间中**覆盖**内置技能（修改行为）
- 用户可以添加**自定义技能**，不影响内置技能
- 升级项目时不会覆盖用户的自定义技能

### 与 Java 类比

类似于 Java 的类加载器优先级：
- 工作空间技能 → 类似于应用类加载器（Application ClassLoader）
- 内置技能 → 类似于扩展类加载器（Extension ClassLoader）
- 同名类/技能优先使用"更近"的加载器

## 3、技能描述文件（SKILL.md）

每个技能目录下必须有一个 `SKILL.md` 文件，它是技能的核心内容，会被加载到 LLM 的上下文中。

### （1）YAML Frontmatter（元数据）

SKILL.md 文件可以在头部包含 YAML frontmatter，定义技能的元数据：

```markdown
---
title: 天气查询
description: 查询全球天气信息
always: false
---

# 天气查询技能

## 功能
查询指定城市的天气信息
...
```

关键字段：

| 字段 | 说明 | 默认值 |
|------|------|--------|
| `title` | 技能显示名称 | 目录名 |
| `description` | 技能简要描述 | 空 |
| `always` | 是否总是加载到系统提示词中 | `false` |

### （2）内容编写规范

SKILL.md 的正文内容会被直接发送给 LLM，因此应该按照"给 AI 写指令"的方式编写：

```markdown
# 天气查询技能

## 功能
查询指定城市的天气信息

## 使用方法
1. 使用 web_fetch 工具访问 wttr.in API
2. 解析返回的天气数据
3. 格式化输出给用户

## API 信息
- 基础 URL: https://wttr.in/{城市名}?format=j1
- 无需认证
- 返回 JSON 格式

## 注意事项
- 城市名使用英文
- 支持中文城市名的拼音
```

## 4、SkillsLoader（技能加载器）

### （1）初始化与加载

```python
class SkillsLoader:
    def __init__(self, skills_dir, builtin_skills_dir=None):
        self.workspace_skills = skills_dir          # 工作空间技能目录
        self.builtin_skills = builtin_skills_dir    # 内置技能目录
        self.skills: dict[str, Skill] = {}          # 已加载的技能 {名称 → Skill 对象}
        self._load_all_skills()                     # 启动时加载所有技能
```

### （2）技能分类方法

```python
def get_always_skills(self):
    """获取标记为 always=true 且满足依赖的技能"""
    return [name for name, skill in self.skills.items()
            if skill.enabled and skill.metadata.get("always")
            and skill.check_requirements()]

def build_skills_summary(self):
    """生成可用技能的简要列表（嵌入到系统提示词中）"""
    lines = []
    for name, skill in sorted(self.skills.items()):
        if skill.enabled and skill.check_requirements():
            desc = skill.metadata.get("description", "")
            title = skill.metadata.get("title", name)
            lines.append(f"- {name} ({title}): {desc}")
    return "\n".join(lines)
```

### （3）技能内容加载

```python
def load_skills_for_context(self, skill_names):
    """加载指定技能的完整内容（用于嵌入系统提示词）"""
    parts = []
    for name in skill_names:
        skill = self.get_skill(name)
        if skill:
            content = self._strip_frontmatter(skill.content)  # 去掉 YAML 头
            parts.append(f"### Skill: {name}\n\n{content}")
    return "\n\n---\n\n".join(parts)
```

### （4）依赖检查

技能可以声明对外部工具或环境变量的依赖：

```python
class Skill:
    def check_requirements(self) -> bool:
        """检查技能依赖是否满足"""
        requires = self.metadata.get("requires", {})
        # 检查二进制依赖（如 ffmpeg、curl 等）
        for binary in requires.get("bins", []):
            if not shutil.which(binary):
                return False
        # 检查环境变量
        for env_var in requires.get("env", []):
            if not os.environ.get(env_var):
                return False
        return True
```

## 5、技能在上下文中的集成

在 ContextBuilder 中，技能被分层集成到系统提示词：

```python
# context.py:40-60
def build_system_prompt(self):
    parts = []
    parts.append(self._get_identity())

    if self.skills:
        # always 技能：直接加载完整内容到提示词
        always_skills = self.skills.get_always_skills()
        if always_skills:
            content = self.skills.load_skills_for_context(always_skills)
            parts.append(f"# 已激活技能\n\n{content}")

        # 按需技能：只提供摘要，AI 需要时通过 read_file 加载
        summary = self.skills.build_skills_summary()
        if summary:
            parts.append(f"# 可用技能\n\n{summary}\n\n"
                        f"**使用方法**: read_file(path='skills/<技能名>/SKILL.md')")
```

这种**分层加载策略**的好处：
- `always` 技能始终在上下文中，AI 可以直接使用
- 按需技能只占用摘要的少量 token，需要时再加载完整内容
- 避免上下文过长导致 LLM 性能下降

## 6、技能管理 API

SkillsLoader 提供完整的增删改查能力：

| 方法 | 功能 |
|------|------|
| `list_skills()` | 列出所有技能（支持过滤已启用/可用的） |
| `add_skill(name, content)` | 添加新技能到工作空间 |
| `update_skill(name, content)` | 更新工作空间技能内容 |
| `delete_skill(name)` | 删除技能 |
| `toggle_skill(name, enabled)` | 启用/禁用技能 |
| `reload()` | 重新加载所有技能（热重载） |

注意：只有工作空间技能可以被修改，内置技能是只读的。

## 8、如何开发自定义技能

### 步骤 1：创建技能目录

在工作空间的 `skills/` 目录下创建：

```
workspace/skills/my-skill/
└── SKILL.md
```

### 步骤 2：编写 SKILL.md

```markdown
---
title: 我的技能
description: 这个技能的简要描述
always: false
---

# 我的技能

## 功能描述
详细描述这个技能能做什么

## 使用方法
告诉 AI 如何使用这个技能

## API 信息（如果有）
描述需要调用的 API

## 示例
给出使用示例
```

### 步骤 3：重启服务或通过 API 重新加载技能

技能加载器支持热重载，可以通过 API 调用 `reload()` 方法重新扫描技能目录。

### 技能开发建议

- 写给 AI 看：SKILL.md 的内容是给 LLM 读的指令，要清晰、具体
- 少用 `always=true`：除非技能非常轻量且高频使用，否则应该按需加载，避免占用 token
- 声明依赖：如果技能依赖外部工具或 API Key，使用 `requires` 字段声明

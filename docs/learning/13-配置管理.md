# 十三、配置管理

配置管理系统负责管理 CountBot 的所有运行参数，包括模型选择、人设配置、渠道设置等。

核心文件：`backend/modules/config/`

```
config/
├── loader.py     # 配置加载器（加载/保存/加密解密）
├── schema.py     # Pydantic 配置模型（定义所有配置项）
└── security.py   # 安全策略定义
```

## 1、配置结构（Pydantic 模型）

`AppConfig` 是配置的顶层模型，包含所有子配置：

```python
# schema.py 中的配置层级
class AppConfig:
    model: ModelConfig           # 模型配置
    workspace: WorkspaceConfig   # 工作区配置
    persona: PersonaConfig       # 人设配置
    security: SecurityConfig     # 安全配置
    channels: ChannelsConfig     # 渠道配置
    providers: dict              # LLM 提供商配置

class ModelConfig:
    provider: str = "zhipu"          # 提供商 ID
    model: str = "glm-4-flash"       # 模型名称
    temperature: float = 0.7         # 生成温度
    max_tokens: int = 4096           # 最大 token
    max_iterations: int = 25         # Agent 最大迭代数

class PersonaConfig:
    ai_name: str = "小C"             # AI 名称
    user_name: str = "用户"           # 用户称呼
    user_address: str = ""            # 用户地址
    personality: str = "professional" # 性格 ID
    custom_personality: str = ""      # 自定义性格文本
    max_history_messages: int = 50    # 最大历史消息数
    heartbeat: HeartbeatConfig        # 心跳配置

class HeartbeatConfig:
    enabled: bool = False             # 是否启用
    schedule: str = "0 * * * *"       # cron 表达式
    channel: str = ""                 # 投递渠道
    chat_id: str = ""                 # 投递聊天 ID
    idle_threshold_hours: int = 4     # 空闲阈值（小时）
    quiet_start: int = 21             # 免打扰开始
    quiet_end: int = 8                # 免打扰结束
    max_greets_per_day: int = 2       # 每日最多问候
```

## 2、配置存储方式

配置以**扁平化的 key-value** 形式存储在 SQLite 的 `settings` 表中：

```
数据库 settings 表：
┌──────────────────────────────────┬──────────────┐
│ key                              │ value        │
├──────────────────────────────────┼──────────────┤
│ config.model.provider            │ "zhipu"      │
│ config.model.model               │ "glm-5"     │
│ config.model.temperature         │ 0.7          │
│ config.providers.zhipu.api_key   │ "sk-xxx"     │
│ config.persona.ai_name           │ "小C"        │
│ ...                              │ ...          │
└──────────────────────────────────┴──────────────┘
```

## 3、ConfigLoader 加载流程

```python
# loader.py
class ConfigLoader:
    async def load(self):
        """从 SQLite 加载配置"""
        # 1. 查询 Setting 表中 key LIKE 'config.%' 的所有记录
        # 2. 遍历结果，去掉 "config." 前缀
        # 3. JSON 反序列化 value（如 '"zhipu"' → "zhipu"）
        # 4. 将扁平 key-value 还原为嵌套字典
        # 5. 用 AppConfig(**嵌套字典) 构造 Pydantic 模型
        # 6. 如果启用了加密，解密 API 密钥

    async def save(self):
        """保存配置到 SQLite"""
        # 1. model_dump() 转为嵌套字典
        # 2. 如果启用了加密，加密 API 密钥
        # 3. 递归扁平化写入 Setting 表（用 merge 实现 upsert）
```

### 扁平化还原示例

```
数据库中的扁平记录                     还原后的嵌套字典

config.model.provider = "zhipu"    →  {"model": {"provider": "zhipu",
config.model.model = "glm-5"      →            "model": "glm-5"},
config.persona.ai_name = "小C"    →   "persona": {"ai_name": "小C"}}
```

## 4、配置来源优先级

```
1. 数据库 Setting 表 （最高优先级）
    ↓
2. 环境变量
    ↓
3. 默认值（Pydantic 模型定义）
```

首次启动时数据库中没有配置，会使用 Pydantic 模型中定义的默认值，并自动写入数据库。

## 5、配置热重载

前端修改配置后，通过 API 调用触发热重载，无需重启服务：

```
PUT /api/settings/model
    │
    ▼
config_loader.update_field("model", new_config)
    │
    ▼
message_handler.reload_config(model=new_model, ...)
    │
    ▼
agent_loop.model = new_model  # 立即生效
```

## 6、API 密钥加密

配置系统支持对 API 密钥进行加密存储：

- **内存中**：始终是明文（程序正常使用）
- **数据库中**：如果启用加密，存储的是密文
- **加载时**：从数据库读取密文 → 解密为明文
- **保存时**：将明文 → 加密为密文写入数据库

加解密失败时不会阻塞程序，而是打 warning 日志继续运行。

## 7、LLM 提供商注册表

核心文件：`backend/modules/providers/registry.py`

### （1）提供商元数据

```python
@dataclass
class ProviderMetadata:
    id: str                     # 唯一标识，如 "openai"
    name: str                   # 显示名称，如 "OpenAI"
    default_api_base: str       # 默认 API 地址
    default_model: str          # 默认模型名
    litellm_prefix: str         # litellm 路由前缀
    env_key: str                # API Key 环境变量名
```

CountBot 预注册了 20+ 提供商，包括 OpenAI、Anthropic、DeepSeek、智谱、通义千问、Moonshot 等。

### （2）LiteLLM 提供商

核心文件：`backend/modules/providers/litellm_provider.py`

LiteLLM 是一个统一 LLM 接口库，CountBot 通过它支持 40+ 模型：

```python
class LiteLLMProvider:
    async def chat_stream(self, messages, tools=None, model=None, ...):
        """流式对话调用"""
        # 使用 litellm.acompletion 调用
        # 将响应转换为统一的 StreamChunk 格式
        # yield 每个 chunk
```

LiteLLM 通过 `前缀/模型名` 路由到不同的 API。例如 `gemini/gemini-2.0-flash` 会路由到 Google Gemini API。

## 8、模块级单例

ConfigLoader 在模块级别创建单例，整个应用共享：

```python
# loader.py 末尾
config_loader = ConfigLoader()
```

其他模块通过 `from backend.modules.config.loader import config_loader` 引用这个实例。这是 Python 中常见的单例模式——模块在首次 import 时执行，后续 import 复用同一个对象。
